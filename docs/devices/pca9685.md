# PCA9685 — `pca9685.py`

- **Status:** new in v0.2.0 Step 5 (ADR-006)
- **Platforms:** Pico (MicroPython) ✓ · Raspberry Pi Linux ✓ · Pi 5 verified ✗ (not yet)
- **pip extra:** `i2c` (smbus2) on Raspberry Pi OS; none on the Pico
- **Last hardware test:** none yet (simulated Pico 2 W and Raspberry Pi OS only)

## Hardware
NXP PCA9685: 16-channel, 12-bit PWM controller on I2C, sold as "16-channel servo
driver" boards (Adafruit 815 and many clones). One frequency (about 24–1526 Hz) for all
16 channels. Datasheet: NXP PCA9685.

- **VCC** (logic): 3.3 V from the Pico/Pi, so the I2C lines stay at 3.3 V.
- **V+** (servo power, screw terminal): separate 5–6 V supply sized for the servos (an
  SG90 can draw ~0.7 A when stalled; an MG996R over 2 A). Never power servos from the
  Pi's 5 V pin.
- Grounds of the servo supply, the board and the Pico/Pi must be connected.
- Address 0x40 with no jumpers; A0–A5 jumpers add 1–63 (0x40–0x7F). Up to 62 boards on
  one bus; avoid 0x70 (the all-call address).
- The internal oscillator is nominally 25 MHz but differs by a few percent between
  boards; if servo pulses measure wrong, set `osc_hz` (e.g. 25_500_000).

## Wiring
| Board pin | Pico pin | Pi header pin (BCM) | Notes |
|---|---|---|---|
| VCC | 3V3 (pin 36) | 3V3 (pin 1) | logic only |
| GND | GND (pin 38) | GND (pin 6) | common with servo supply |
| SDA | GP0 (pin 1), I2C0 | GPIO2 / SDA1 (pin 3) | any I2C-capable pair on the Pico |
| SCL | GP1 (pin 2), I2C0 | GPIO3 / SCL1 (pin 5) | |
| OE | — | — | leave unconnected (pulled low = outputs on) |
| V+ | — | — | 5–6 V servo supply |

On a Pi, enable I2C first: `sudo raspi-config` → Interface Options → I2C. Check the
board answers: `i2cdetect -y 1` shows `40`.

## API
```python
# Pico
from machine import I2C, Pin
board = PCA9685("servos", i2c=I2C(0, sda=Pin(0), scl=Pin(1), freq=400000), app=self)
# Raspberry Pi OS
board = PCA9685("servos", i2c=1, app=self)
```

| Member | Description |
|---|---|
| `PCA9685(name=None, i2c=None, address=0x40, freq=50, osc_hz=25000000, log_func=None, app=None)` | Sets the frequency, totem-pole outputs, all channels off. Pico: `i2c` is a `machine.I2C` (borrowed). Pi: bus number (default 1, opened and closed by the board) or an open `smbus2.SMBus` (borrowed). |
| `freq` | Actual PWM frequency in Hz (from the prescaler). |
| `set_pulse_us(ch, us)` | Pulse of `us` µs each period (servos). |
| `set_duty(ch, percent)` | Duty cycle 0–100 % (LEDs); 0 = fully off, 100 = fully on. |
| `channel_off(ch)` / `all_off()` | No output on one / all channels. |
| `claim_channel(ch, owner)` / `release_channel(ch)` / `channel_owners` | Channel reservation; servos claim theirs automatically. |
| `close()` | All channels off, chip asleep, owned bus closed. Idempotent. |

Servos: `PositionalServoManager("pan", pca=board, channel=0, app=self)` — see
`positional_servo_manager.md`.

## Platform differences
- Pico: register writes with `I2C.writeto_mem`; the app creates the bus and may share it
  with other I2C devices. Pi: smbus2 block writes; a bus number is owned by the board.
- Behaviour on the chip is identical.

## Safe state
- At construction: chip asleep while the prescaler is set, every channel full off, then
  awake. No pulse is output until a channel is set.
- After `close()` (app stop, Ctrl-C, crash with `app=self`): every channel full off and
  the oscillator stopped (SLEEP). Servos go limp.
- Servos created after the board are closed before it (registry closes newest first);
  if the board is closed first, its servos still close without error.
- Not covered by software: power-up of the board before the program runs (outputs
  default to off on the chip), and loss of I2C mid-run (outputs keep their last value).

## Known issues / TODO
- One frequency per board: servos (50 Hz) and LED dimming share it.
- No register read-back or "all-call"/sub-address support.
- I2C register access is private to this module; the `ADS1x15` group may extract a
  shared helper (separate ADR).
- Not yet verified on a Pico 2 W, Pi 4 or Pi 5.
